# C0 records

Two gates, both offline and deterministic, both required.

## `program_c0` — C0-CATALOGUE-UNIVERSE, 28/28

Regenerated by `c0_verify` and `c0_demo` against a clean tree. **`data_kind` is
`SYNTHETIC` by design**: these fixtures have closed-form correct answers, which is
what makes them able to verify the machinery. No number in this directory is an
astronomical measurement, and the gate's first case asserts that the fixtures say
so.

## `../program_c0_real` — C0-REAL-CATALOGUE, 15/15

The other half: real Gaia DR3 records, retrieved over TAP by
`tools/import_gaia.py`, checked against independently published astronomy. Reads
the committed `snapshots/gaia_dr3_5pc.txt`, so it touches no network.

`c0_demonstration_gaia_dr3_10pc.txt` in this directory is the same demonstration
run against the real 10 pc volume — 315 Gaia DR3 sources, Proxima Centauri at
1.30197 pc — beside `c0_demonstration.txt`, which is the synthetic run. Compare
the two: the `DATA KIND` header is the difference, and it is the first line of
each.

| File | Contents |
| --- | --- |
| `verification_report.md` | all 28 cases, with claim, computed value and tolerance |
| `verification_summary.json` | machine-readable pass/fail and build provenance |
| `verification_table.csv` | the same cases as a table |
| `c0_metadata.json` | pinned release, TAP endpoint, ADQL, ingestion ledger, `data_honesty` |
| `c0_manifest.txt` | release, checksum, row counts, every rejection *with its reason*, estimator counts, missing-field counts, uncertainty summary, volume counts, and the ADQL marked NOT ISSUED |
| `c0_validation_objects.csv` | the named validation set, each row tagged with its data kind |
| `c0_snapshot_50pc.txt` | the versioned, checksummed snapshot itself — the authoritative store |
| `c0_demonstration.txt` | the offline demonstration output |

## Regenerating

```
c0_verify --out <this dir>
c0_demo   --out <this dir>
```

## The database

The snapshot is the authoritative store. To materialise it as real SQLite:

```
python ../../../tools/snapshot_to_sqlite.py c0_snapshot_50pc.txt --out stars.sqlite --demo
```

The `.sqlite` file is deliberately **not** committed — it is a pure projection of
`c0_snapshot_50pc.txt`, whose FNV-1a checksum is the database's provenance, and
the tool refuses to build from a snapshot that fails it.

## Getting real data

```
python ../../../tools/import_gaia.py --radius-pc 50 --out snapshot_gaia_dr3_50pc.txt
```

That snapshot's `data_kind` will read `Gaia DR3` rather than `SYNTHETIC`, and it
will carry a real retrieval timestamp. Until then, read every number here as a
statement about the code, not about the sky.
